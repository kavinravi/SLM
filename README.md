# SLM -- Small Language Model

Training a GPT-style transformer from scratch on a **synthetic, textbook-quality corpus**, on a single RTX 5090 (32GB VRAM).

## Why synthetic data

The earlier version of this model trained on ~25B tokens of raw web text and plateaued at *fluent but incoherent* -- grammatical sentences with no factual grounding, no focus, and topic drift. The cause was data: low-quality, noisy web text, and not enough of it for a model this size.

This redesign replaces scraped web text with a controlled, high-quality synthetic corpus generated by a language model across thousands of topics -- the same idea behind Phi, Cosmopedia, and TinyStories. The trade is deliberate: we give up open-web factual breadth in exchange for clean signal and coherence, which is the right trade for a small model. The model will read as somewhat "model-generated," but coherent.

## Model

| | |
| --- | --- |
| Architecture | Decoder-only transformer (GPT-style) |
| Parameters | ~538M |
| Hidden dim | 1280 |
| Attention heads | 20 |
| Layers | 24 |
| FFN dim | 5120 |
| Context length | 2048 tokens |
| Precision | bf16 (via `torch.amp.autocast`) |
| Attention | PyTorch SDPA (flash backend, `is_causal=True`) with **QK-norm** |
| Position encoding | Learned absolute |
| Weight tying | Embedding and LM head share weights |
| Tokenizer | Custom 50k-vocab byte-level BPE |

QK-norm is the one architectural change from the previous version; it stabilizes training and removes the loss/gradient spikes that previously forced repeated restarts.

## Data pipeline

The corpus is built, not scraped:

1. **Seed topics** -- ~1000 broad encyclopedic areas (science, history, geography, arts, technology, everyday life, ...).
2. **Topic expansion** -- a language model expands each seed into ~30-50 narrow subtopics, yielding tens of thousands of fine-grained leaves. Diversity comes from breadth of subtopics, not from re-prompting the same broad topic (which collapses to a few popular angles).
3. **Generation** -- for each `(subtopic x audience/complexity x format)` cell, a language model writes self-contained documents (textbook section, FAQ, how-to, dialogue, story, ...) as raw text.
4. **Build** -- documents are deduplicated (exact + near-duplicate), filtered, and packed into 2048-token blocks stored as a `uint16` memmap (`data/train_tokens.npy`) with a held-out validation split.

Target: a large corpus (100GB+ of generated text) trained for multiple epochs, with the model retrained incrementally as the corpus grows.

## Training

- **Optimizer:** AdamW (fused, weight decay on 2D+ params only)
- **Schedule:** cosine decay with linear warmup
- **Effective batch size:** ~524k tokens (micro-batch x grad accum x 2048 seq len)
- **Memory:** gradient checkpointing, `torch.compile`
- **Tracking:** [Trackio](https://github.com/gradio-app/trackio) -- free, local-first experiment tracking that syncs to a Hugging Face Space, so training can be monitored remotely without a paid subscription

```
.
|- train.ipynb       # Model definition, data pipeline, training, eval
|- inference.ipynb   # Load a checkpoint and generate text
|- config.yaml       # All hyperparameters
|- requirements.txt  # Dependencies (pinned to PyTorch cu128 for RTX 5090)
|- tokenizer/        # Saved tokenizer artifacts (generated, gitignored)
|- data/             # Generated corpus + packed tokens (generated, gitignored)
|- checkpoints/      # Model checkpoints (generated, gitignored)
```

## Requirements

- NVIDIA RTX 5090 (or any Blackwell GPU with CUDA 12.8)
- Python 3.10+ (developed on 3.12)
- PyTorch >= 2.7.0 with CUDA 12.8
- A free Hugging Face account for remote tracking via Trackio (optional)
